# Security

This project is research software without a long-term support release policy.
Security fixes target the main branch.

If GitHub private vulnerability reporting is enabled, use **Security → Report
a vulnerability**. Otherwise ask for a private reporting channel in an issue,
without including vulnerability details. Do not post credentials or sensitive
reproducer data in public issues.
Ordinary numerical and physics correctness problems belong in the issue tracker.

Archives and external installations should come from trusted sources. Checksums
verify file identity; they do not authenticate a producer's physics declarations.
